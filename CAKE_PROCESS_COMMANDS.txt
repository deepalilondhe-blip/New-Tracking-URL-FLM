================================================================================
                    1. NON-TEST & TEST PROCESS
================================================================================

Description:
  This is the ORIGINAL Cake process that validates Test & Non-Test 
  conversion records. It searches for red rows in QA affiliate data 
  and sends email notifications for identified issues.

File Location:
  CakeProcess.js/cake.js

COMMAND 1: Run with Visible Browser (Headed Mode)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  node CakeProcess.js\cake.js --non-test-procedure --headed --hold=180

  Breakdown:
  ├─ node                          : Execute Node.js script
  ├─ CakeProcess.js\cake.js        : Path to the script
  ├─ --non-test-procedure          : Run the Non-Test & Test validation
  ├─ --headed                      : Run with visible browser (can watch)
  └─ --hold=180                    : Hold for 180 seconds before closing

  Expected Output:
  ├─ Browser will open and show Cake CRM
  ├─ Navigates to REPORTS > Conversions
  ├─ Applies Tests & Non-Tests filter
  ├─ Searches for QA Affiliate rows
  ├─ Scans for red rows (failures)
  └─ Generates report in CakeProcess.js/


COMMAND 2: Run in Headless Mode (Faster)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  node CakeProcess.js\cake.js --non-test-procedure

  Breakdown:
  ├─ Removes --headed flag (runs in background)
  ├─ Runs faster (no visual browser rendering)
  └─ Still generates all reports and emails

  When to Use:
  ├─ Scheduled execution
  ├─ When visual monitoring not needed
  └─ For faster batch processing


COMMAND 3: Manual Mode (With Manual Steps)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  node CakeProcess.js\cake.js --non-test-procedure --headed --manual-login

  Features:
  ├─ Allows manual login before automation
  ├─ Useful if automatic login fails
  ├─ Headed mode (visible browser)
  └─ Proceed after manual login


COMMAND 4: Custom Hold Time (Adjust Timeout)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  node CakeProcess.js\cake.js --non-test-procedure --headed --hold=300

  Adjustment:
  ├─ --hold=180  : Wait 180 seconds (default)
  ├─ --hold=300  : Wait 300 seconds (5 minutes)
  ├─ --hold=60   : Wait 60 seconds (1 minute)
  └─ Adjust as needed for your use case

  ├─ Extracts Page Origin URL from the Vertical Specific tab

├─ Focus: Red rows and QA affiliates
├─ Output: CakeProcess.js/ directory

Process 2: Test Only (cake_test_only.js) [NEW & INDEPENDENT]
├─ Filter: Test Only
├─ Focus: Test user validation
├─ Output: CakeProcess.js/test_only_*/ directories
├─ Command: node CakeProcess.js\cake_test_only.js --headed


RUN BOTH PROCESSES SEQUENTIALLY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Option 1: Run one after another manually
───────────────────────────────────────

  Step 1: Run Non-Test & Test Process
  node CakeProcess.js\cake.js --non-test-procedure --headed

  Wait for completion...

  Step 2: Run Test Only Process
  node CakeProcess.js\cake_test_only.js --headed

  Wait for completion...

  Done! Both processes completed with separate reports


Option 2: Run both sequentially in terminal
───────────────────────────────────────────

  node CakeProcess.js\cake.js --non-test-procedure --headed && node CakeProcess.js\cake_test_only.js --headed

  Note:
  ├─ && : Run second command only if first succeeds
  ├─ This runs both automatically in sequence
  └─ Each generates its own report


Option 3: Run independently in parallel (Advanced)
──────────────────────────────────────────────────

  # In Terminal 1:
  node CakeProcess.js\cake.js --non-test-procedure --headed

  # In Terminal 2 (simultaneously):
  node CakeProcess.js\cake_test_only.js --headed

  Note:
  ├─ Requires two separate terminal windows
  ├─ Both run at the same time
  ├─ Independent browser instances
  └─ No conflicts or interference

Creating Custom Batch Files
────────────────────────────

  If you want to create custom batch files, use this template:

  @echo off
  REM Description of what this batch file does
  
  echo Starting [PROCESS NAME]...
  cd /d "%~dp0"
  
  node [SCRIPT_PATH] [ARGUMENTS]
  
  pause

  Example: Create run_non_test.bat
  ─────────────────────────────────

  @echo off
  REM Non-Test & Test Process
  
  echo Starting Non-Test & Test Process...

                    6. STEP-BY-STEP EXECUTION GUIDE
================================================================================

SCENARIO 1: Run Test Only Process (Most Common)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Step 1: Open VS Code Terminal
  ├─ Ctrl + ` (backtick)
  ├─ Or: Terminal → New Terminal
  └─ Make sure you're in project root

  Step 2: Copy & Execute Command
  ├─ Copy: node CakeProcess.js\cake_test_only.js --headed
  ├─ Paste into terminal
  ├─ Press Enter
  └─ Watch the browser open

  Step 3: Monitor Execution
  ├─ Observe browser navigation
  ├─ Check console for log messages
  ├─ Wait for process to complete
  └─ Press any key to close terminal (if using batch)

  Step 4: Check Results
  ├─ Open: CakeProcess.js/test_only_reports/
  ├─ View: execution_[timestamp].log
  ├─ View: test_only_report_[timestamp].json
  ├─ Open: CakeProcess.js/test_only_screenshots/
  └─ Review: Screenshots for validation


SCENARIO 2: Run Non-Test & Test Process
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Command: node CakeProcess.js\cake.js --non-test-procedure --headed

  Same steps as Scenario 1, but:
  ├─ Uses different script (cake.js)
  ├─ Applies different filter (Tests & Non-Tests)
  ├─ Outputs to CakeProcess.js/ directory
  └─ Looks for red rows in QA data


SCENARIO 3: Run Both Processes Back-to-Back
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Command: node CakeProcess.js\cake.js --non-test-procedure --headed && node CakeProcess.js\cake_test_only.js --headed

  Step 1: Paste command into terminal
  Step 2: Press Enter
  Step 3: First process runs (Test & Non-Test)
  Step 4: After completion, second process runs (Test Only)
  Step 5: Both reports generated separately
  Step 6: Done!

  Note: This may take 1-2 minutes total
